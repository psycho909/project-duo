完整偵測數據

在實機上複製後貼回來，用來校正判斷門檻。

四種版型，目前套用的是哪一種

  1. A. 窄版單視窗

    外螢幕、內螢幕分割視窗、浮動視窗都在這類。單欄內容、底部導覽、點清單項目後換頁看詳細內容。實體是內螢幕也一樣：網頁只拿到一半寬度，就照手機版設計。

  2. B. 寬版連續畫面

    Z Fold8、iPhone Duo 展開內螢幕且網頁佔滿整片。雙欄 list-detail，導覽移到側邊。畫面正中央就是摺痕，避免把按鈕、標題斷行或影片中心放在 50% 寬處。

  3. C. 跨摺痕分區（左右）

    瀏覽器回報兩個 viewport segment 時才啟用。兩欄各對齊一個 segment，轉軸區不放文字或按鈕。適合左清單右內容、左原文右翻譯。

  4. D. 半摺，上下分區

    筆電／桌上模式。上半部放內容（影片、圖片、地圖），下半部放操作（播放控制、留言、鍵盤）。

模擬其他裝置

尺寸是估計值：Z Fold8 依前代推估，iPhone Duo 依傳聞規格。拿到實機數據後，修改程式中的 PRESETS。

判斷邏輯

  • 螢幕數量：window.viewport.segments 回報 2 個以上分區，就是跨摺痕（C 或 D）。目前只有支援 Viewport Segments API 的 Chromium 瀏覽器會回報，iOS Safari 不支援。
  • 內螢幕或外螢幕：看實體螢幕形狀。長邊除以短邊小於 1.5 且短邊至少 600px 是內螢幕；短邊小於 520px 是外螢幕或一般手機。
  • 連續畫面或多工視窗：視窗寬度不到螢幕的 90%，或高度不到 70%，代表分割畫面或浮動視窗，當作單螢幕處理。
  • 最後由視窗寬度決定版型：小於 600px 單欄，600px 以上雙欄。裝置狀態只用來微調細節，這是 Material 3 與 Apple 自適應版面目前的共同做法。
純 CSS 寫法 
/* A：窄版單欄（預設） */
.app { display: grid; grid-template-columns: 1fr; }

/* B：寬版連續畫面 → 雙欄 */
@media (min-width: 600px) {
  .app { grid-template-columns: 2fr 3fr; }
}

/* C：左右兩個 segment → 依摺痕對齊 */
@media (horizontal-viewport-segments: 2) {
  .app {
    grid-template-columns:
      env(viewport-segment-width 0 0)
      calc(env(viewport-segment-left 1 0) - env(viewport-segment-right 0 0))
      env(viewport-segment-width 1 0);
  }
}

/* D：上下兩個 segment（半摺／筆電模式） */
@media (vertical-viewport-segments: 2) {
  .app {
    grid-template-rows:
      env(viewport-segment-height 0 0)
      calc(env(viewport-segment-top 0 1) - env(viewport-segment-bottom 0 0))
      env(viewport-segment-height 0 1);
  }
}

/* 摺疊姿態（Device Posture API） */
@media (device-posture: folded) { /* 書本／筆電姿勢 */ }
