## 寬度分布

```
349 360 373 | 414 | 463 475 ‖ 663 | 704 704 | 752 752 756 ‖ 834 834 | 932
└──── 單欄（349–475）────┘    └───── 中寬（663–756）─────┘   └ 寬版 ┘
```

- 單欄 349–475：兩台外螢幕直向、所有左右分割
- 中寬 663–756：Fold8 內直、兩台外螢幕橫向、內直上下分割
- 寬版 834–932：兩台內螢幕橫向

## 建議斷點

```css
/* 單欄：< 600 */
@media (min-width: 600px) { /* 中寬：663–756 */ }
@media (min-width: 800px) { /* 寬版：834–932，雙窗格 */ }
@media (max-height: 460px) { /* 矮畫面：外螢幕橫向、上下分割（223–445） */ }
```

- 600：475 與 663 之間的空白很大，用 Material 3 的 600 即可。
- 800：756 與 834 的中點約 795。若照 Material 3 的 840，Ultra 內螢幕橫向的 834 會被歸到中寬，因此改用 800。
- `max-height: 460px`：矮畫面最高 445，其餘最低 520。
- 單欄內 349–475 差 126px，用流動寬度處理；若要再細分，可加 400。
- 高度請用 `svh`／`dvh`，不要用 `vh`：內螢幕的網址列差 96px。

## 判斷邏輯需要調整的地方

- Fold8 外螢幕橫向（663 × 389）被判成「multi」，實際上是全螢幕。原因是寬度只佔螢幕的 88%，低於門檻 90%（側邊導覽列佔掉寬度）。
- 全螢幕狀態的最低佔比：寬 88%、高 74%。
- 分割視窗的佔比：寬 ≤ 75% 或高 ≤ 57%。
- 建議門檻改為「寬 < 80% 或 高 < 65%」，可以把這次所有狀態分對。

## 原始紀錄的筆誤

- Fold8 第二個「雙螢幕 直: 704 x 749」區塊，內容其實是內螢幕橫向 932 × 520 的重複資料。
- Ultra「橫 雙螢幕 834 x 578」那筆的 innerHeight 為 674（網址列收起），與上面「橫: 834 x 578」是同一狀態。
- 標題的高度多數是 `100svh`，不是 `innerHeight`。
