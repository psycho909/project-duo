# RWD 臨時規範 × 摺疊機實測比對（2026-11-02）

依據：

- 公司 RWD 臨時規範：≤ 480 vw 縮放、481–768 vw 縮放、≥ 769。
- 附錄的 iPhone 尺寸，**未實測**。
- [LambdaTest 量測](lambdatest-2026-11-02.md)：Galaxy Z Fold8、Fold8 Ultra。

寬 × 高的高度一律取 `100svh`（網址列顯示時，可用高度最小的情況）。

- 結論：**480／768 這兩個斷點和實測數據對得上**。
  - 757–833 之間沒有任何實測寬度，768 剛好落在空白處。
  - 476–625 之間也沒有，480 在空白區的邊緣。
- 規範本身不用改分段，但缺了下面幾項，照現在的寫法做會出問題。

## 2. 不足的地方

### 2-1 沒有定義設計畫板寬度

「用 vw 縮放」必須先有基準寬，才算得出 `16px = ?vw`。規範沒寫，營運每次給的稿寬不同，前端就得各自換算。

### 2-2 ≤ 480 會放大到 1.27 倍

- 寬螢幕的外螢幕會整頁放大成「大字版」：Fold8 外螢幕 475、iPhone Duo 外螢幕 466、Fold8 橫向分割 463。
- 但這些畫面的使用者預期是看到更多內容，不是更大的字。
- 以 375 畫板計算，16px 的字在 475 寬會變成 20px，按鈕、間距也一起變大。

### 2-3 矮畫面被當成平板或桌機

- 外螢幕橫向和上下分割的寬度是 663–834，高度卻只有 223–389，會依寬度套用 481–768 或 ≥ 769 的版。
- 例如 Fold8 Ultra 外螢幕橫向 756 × 274，會用平板版的 vw 縮放，首屏 KV 一張就超過整個畫面高度。
- iPhone 18 Pro Max 橫向約 956 寬，會吃到桌機版。

### 2-4 ≥ 769 沒寫縮放方式，也沒寫下限

- 摺疊機內螢幕橫向是 834 × 578 和 932 × 520，會進到桌機版。
- 如果桌機版是 1200px 以上的固定寬度，在 834 寬會出現水平捲軸或被截掉。
- 若改成用 vw 從 1200 縮下來，834 寬只剩 0.70 倍，16px 的字變成 11px。

### 2-5 純 vw 字級不跟系統字級

- 使用者在手機設定裡調大字級時，vw 字不會變，不符合 WCAG 1.4.4 文字縮放的要求。
- 481–768 這段在 Duo 內螢幕（626）是 0.87 倍，16px 的字會變成 14px。

### 2-6 每台摺疊機一轉向就換級距

| 裝置 | 直向 | 橫向 |
|---|---|---|
| Fold8 內螢幕 | 704（481–768） | 932（≥ 769） |
| Fold8 Ultra 內螢幕 | 752（481–768） | 834（≥ 769） |
| Fold8 外螢幕 | 475（≤ 480） | 663（481–768，矮畫面） |

- 規範寫「收到特別需求才提供」，但摺疊機使用者只要轉個方向，三套版都會看到。
- 換版時，輪播目前在第幾張、影片播放進度、表單內容不能重置。

### 2-7 沒有 KV／主視覺的安全區

三個級距的長寬比差很多，同一張 KV 直接縮放一定會裁掉主體：

| 級距 | 長寬比範圍 | 畫面形狀 |
|---|---|---|
| ≤ 480 | 0.44–0.89 | 細長直向到近方形 |
| 481–768（不含矮畫面） | 0.70–1.15 | 直向到近方形 |
| ≥ 769（摺疊機） | 1.44–1.79 | 橫向 |

另外，內螢幕展開時，**畫面中線是實體摺痕**，KV 主角的臉、標題、主要按鈕不要正好壓在中線上。

### 2-8 斷點寫法有縫

- `max-width: 480px` 加上 `min-width: 481px` 的寫法，碰到小數寬度（例如 480.5px，DPR 2.625 的裝置可能出現）時，兩條都不成立。
- 改用範圍語法 `(width <= 480px)`、`(480px < width <= 768px)`、`(width > 768px)` 就不會有縫。

### 2-9 ≥ 769 在摺疊機上是觸控，不是滑鼠

- 桌機版常用的 hover 選單、hover 才出現的按鈕，在內螢幕橫向會點不到。
- hover 效果要包在 `@media (hover: hover)` 裡，並且一定要有點擊的替代方式。

### 2-10 圖片輸出尺寸沒定

- 實測 DPR 是 2.625–3，iPhone 也是 3。
- 依目前寫法，≤ 480 的圖最大會顯示到 475 寬 × 3，需要 1425px 寬的圖；給 750px 的 2 倍圖會糊。

### 2-11 iPhone Duo 的尺寸還沒驗證

- 附錄的 466 × 678、626 × 890 不確定含不含 Safari 的網址列和工具列。
- iOS Safari 不支援摺痕偵測 API，所以只能用寬度判斷。
- 拿到實機後，請用 https://project-duo.netlify.app/ 量一次。

## 3. 調整後的臨時規範（建議版）

分段不變，補上畫板、倍率上下限、矮畫面、桌機版下限。

| 級距 | 範圍 | 設計畫板 | 縮放方式 | 內容最寬 | 圖片輸出 |
|---|---|---|---|---|---|
| **A 手機** | `width <= 480` | **375**（2 倍稿 750） | vw 等比，上限 1.17 倍 | 440px，超過置中 | 畫板 × 3 = 1125 寬（KV 可到 1320） |
| **B 平板／內螢幕直** | `480 < width <= 768` | **720**（2 倍稿 1440） | vw 等比，上限 1.07 倍 | 768px | 畫板 × 3 = 2160 寬 |
| **C 桌機／內螢幕橫** | `width > 768` | **1200** 內容寬（PC 稿 1920） | px，769–1199 流動 | 1200px | 2 倍 = 2400 寬 |
| **矮畫面** | `orientation: landscape` 且 `height <= 460` | 沿用 **A 版** | 不放大（1 倍），置中 | 375px | 同 A |

各項的理由：

- **A 用 375 畫板**：實測寬 349–475 都落在 0.93–1.17 倍之間；上限 440 對齊 iPhone 18 Pro Max，再寬的 Fold8 外螢幕和 Duo 外螢幕就兩側留白，不再放大。
- **B 用 720 畫板**：Fold8 內直 704 是 0.98 倍、Ultra 內直 752 是 1.04 倍；Duo 內螢幕 626 是 0.87 倍，字級用 `max(1rem, …)` 保底。
- **C 用流動排版、不用 vw**：內螢幕橫向的長寬比 1.44–1.79，接近桌機的 16:9，用桌機版的排版最合適。但 769–1199 要用流動寬度，不能固定 1200。
- **矮畫面 460**：實測的矮畫面最高 389（不含網址列收起），一般畫面最低 520，460 剛好分得開。

### 3-1 前端寫法

```css
:root {
  --base: 375;      /* 設計畫板寬 */
  --max: 440px;     /* 內容最寬，超過就置中、不再放大 */
  --u: calc(min(100vw, var(--max)) / var(--base));  /* 設計稿的 1px */
}
@media (480px < width <= 768px) { :root { --base: 720; --max: 768px; } }
@media (width > 768px)           { :root { --u: 1px; --max: 1200px; } }
@media (orientation: landscape) and (height <= 460px) {
  :root { --base: 375; --max: 375px; --u: 1px; }  /* 矮畫面：沿用 A 版、不放大 */
}

.page  { max-width: var(--max); margin-inline: auto; }
.title { font-size: max(1.25rem, calc(28 * var(--u))); }  /* 字級至少跟著系統字級 */
.card  { padding: calc(24 * var(--u)); border-radius: calc(12 * var(--u)); }
@media (hover: hover) { .card:hover { /* hover 效果只給滑鼠 */ } }
```

- 設計稿標幾 px，就寫 `N * var(--u)`，不用自己換算 vw。
- 欄寬、容器寬一律用 `%`、`fr`，不要用 `--u`。
- 首屏高度用 `100svh`，不要用 `100vh`：實測網址列差 56–96px。

### 3-2 營運交稿清單

每個活動需要的設計稿：

| 稿件 | 尺寸 | 用途 |
|---|---|---|
| A 版 | 375 寬（或 750 的 2 倍稿） | 手機、外螢幕、分割視窗、矮畫面 |
| B 版 | 720 寬（或 1440 的 2 倍稿） | 內螢幕直向、iPhone Duo 內螢幕 |
| C 版 | PC 1920 寬、內容 1200 | 桌機、內螢幕橫向 |

檢查用的畫框（不用另外出稿，用來確認 KV 不會被裁）：

| 版本 | 檢查尺寸 |
|---|---|
| A | 349 × 790（最窄）、475 × 605（最寬，置中留白） |
| B | 626 × 890（最高）、752 × 653（最扁） |
| C | 834 × 578（最窄）、932 × 520 |
| 矮畫面 | 756 × 274 |

KV 安全區：

- 主角、標題、按鈕放在畫面中央 **60% 寬 × 60% 高** 的範圍內。
- B、C 版要避開正中線左右各 **24px**（內螢幕摺痕的位置）。

## 4. 還沒涵蓋、需要實機確認的

- **iPhone Duo**：附錄尺寸未實測，也還沒量過橫向、分割視窗、Safari 工具列的高度。
- **跨摺痕與半摺**：Galaxy 的 Flex 模式、跨摺痕狀態在 LambdaTest 量不到。臨時規範先當成一般單一畫面處理。
- **Samsung Internet**：網址列高度可能和 Chrome 不同。
- **浮動視窗**：沒有實測數據。依寬度落點，應該都會進 A 版。
- **系統字級調大**：要確認 `max(1rem, …)` 保底後，版面不會爆版。
